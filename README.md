# Omed

[![codecov](https://img.shields.io/codecov/c/github/kilip/omed)](https://codecov.io/gh/kilip/omed)

A demo project on steroids

The monorepo is managed with [Bun workspaces](https://bun.sh/docs/install/workspaces) and [Turborepo](https://turbo.build/repo).

## Repository Structure

```
omed/
├── apps/
│   ├── api/           # @omed/api         - REST backend (Go, Fiber v3, Ent, Casbin, Swaggo)
│   └── web/           # @omed/web         - Web dashboard (React Router v8 SPA, Ant Design)
├── packages/
│   ├── openapi/       # @omed/openapi     - TypeScript types generated from the `apps/api` OpenAPI spec
│   └── tsconfig/      # @omed/tsconfig    - Shared base tsconfig
├── e2e/               # e2e               - End-to-end tests (Cucumber + Playwright)
├── .devcontainer/     # Full dev environment (tools + Postgres, Redis, RustFS, Kafka)
├── .github/           # CI, image builds, release-please, Renovate
├── AGENTS.md          # Conventions for AI coding agents (CLAUDE.md and GEMINI.md point here)
├── BRANDING.md        # Dashboard visual guidelines / design tokens
└── turbo.json
```

| Package | Description | Port |
| --- | --- | --- |
| `apps/api` | REST backend. Authentication, sessions, Ent ORM, Casbin authorization, OpenAPI v3.1 spec via Swaggo. | 8001 |
| `apps/web` | SPA dashboard (`ssr: false`) with a module launcher and i18n (id/en). | 3000 |
| `packages/openapi` | `src/api.ts` generated by `openapi-typescript`, consumed by `openapi-fetch` in the dashboard. | - |
| `e2e` | End-to-end tests (Cucumber + Playwright). | - |

## Architecture

```
 Browser ──► apps/web ──► apps/api ──► Postgres (Ent)
```

- `apps/api` handles identity, sessions, and is the source of truth for users, workspaces, and memberships.
- Authorization in `apps/api` is **workspace based**: every user gets a personal workspace, can create more, and can invite other users. Roles are assigned per workspace membership, and a user can only access or read workspace resources when they are a member or owner of that workspace.
- Modules in `apps/api` register their roles & permissions in code via `authz.AddRole` in `init()` (e.g. `fin:accountant` -> `fin:invoice read`). Permissions are verified per-request using an in-memory Casbin enforcer based on resolved workspace membership.
- The dashboard is split into modules (`core`, `fin`, `cms`), each under `apps/web/app/modules/<module>/`. A module declares its routes in `route.ts` and its launcher metadata (label, icon, etc.) in `module.ts`; there is no central registry file.
  - **Finance (`fin`) module routes & capabilities:**
    - `/fin`: Finance dashboard with financial overview and status metrics.
    - `/fin/setup`: Template-based initial Chart of Accounts setup (`POST /workspaces/{wid}/fin/accounts/seed`).
    - `/fin/accounts`: Tree-table Chart of Accounts with account type, balance classification, active state, and ledger navigation.
    - `/fin/transactions`: Business transactions list with search and filtering by reference/source/date, and drawer for creating transactions with optional inline entries.
    - `/fin/transactions/:id`: Transaction detail screen with editable header (for draft entries), list of associated journal entries, and entry creation modal.
    - `/fin/journal`: Journal entries list with search and filtering by status/date/period, and drawer for creating balanced double-entry vouchers (`PostingsEditor`).
    - `/fin/journal/:id`: Journal entry detail view with status workflow (post, reverse with date override, void) and individual postings linked to the ledger.
    - `/fin/ledger`: General Ledger view (`GET /workspaces/{wid}/fin/accounts/{id}/ledger`) with account selector, running balances, and direct deep-links to journal entries.
    - `/fin/trial-balance`: Financial trial balance reports and summaries.
  - **CMS (`cms`) module routes & capabilities:**
    - `/cms/posts`: Post list with search, status filters (Draft, Scheduled, Published), and actions.
    - `/cms/posts/new`: Create post with title, auto-slug, excerpt, markdown editor (write/preview), and cover media picker.
    - `/cms/posts/:id`: Post detail and edit with PublishPanel (Publish now, Schedule, Unpublish), cover media picker, inline slug conflict handling, and deletion.
    - `/cms/pages`: Standalone pages list with search, status filters, and actions.
    - `/cms/pages/new`: Create page with title, auto-slug, and markdown editor.
    - `/cms/pages/:id`: Page edit with PublishPanel and deletion.
    - `/cms/media`: Media library with drag-and-drop / upload, metadata editing (title, alt text, caption, public toggle), copy public URL, and in-use delete protection.
  - **Admin and public API summary:**
    - Admin API: authenticated workspace-scoped CRUD and publishing endpoints under `/workspaces/:wid/cms/{posts,pages,media}`.
    - Public API: unauthenticated read-only endpoints under `/public/workspaces/:wid/cms/{posts,pages,media}`.

## Tech Stack

- **Backend & Auth:** Go, Fiber v3, Ent, Casbin, Swaggo
- **Frontend:** React 19, React Router v8 (SPA), Ant Design 6, Tailwind CSS 4, i18next
- **Data / infra (devcontainer & CI):** PostgreSQL 18, Redis 8, RustFS (S3-compatible), Apache Kafka (KRaft)
- **Tooling:** Bun, Turborepo, Biome, Husky + Commitlint, Air, Swag, Vitest, Cucumber, Playwright

> Redis, S3 (RustFS), and Kafka are currently only provisioned in the devcontainer and CI; no application code uses them yet.

## Prerequisites

- [Bun](https://bun.sh) `1.4.2` and Node.js `>= 22`
- [Go](https://go.dev) `1.27` (see `apps/api/go.mod`)
- Docker & Docker Compose (Postgres and supporting services)
- **Go tools:** [`air`](https://github.com/air-verse/air), [`swag`](https://github.com/swaggo/swag) v2, and [`atlas`](https://atlasgo.io)

> Easiest path: open the repo in the **devcontainer** (or GitHub Codespaces). All tools, services, and environment variables are prepared, and `bun install` runs automatically.

## Getting Started

```bash
git clone https://github.com/kilip/omed.git
cd omed

bun install            # also installs git hooks (husky)
cd apps/api && go mod tidy && cd ../.. # sync Go dependencies

bun run db:migrate     # apply versioned multi-schema Atlas migrations
bun run dev            # run all apps (turbo)
```

Run a single app:

```bash
bunx turbo run dev --filter=@omed/api
bunx turbo run dev --filter=@omed/web
```

Once running: dashboard at <http://localhost:3000>, API at <http://localhost:8001>.

### Environment

In the devcontainer all values below are set through `.devcontainer/compose.yaml`. Outside the devcontainer, each app reads its own git-ignored `.env`: copy `apps/api/.env.example` and `apps/web/.env.example` to `.env` in the same directory (`cp apps/<app>/.env.example apps/<app>/.env`).

| Variable | Used by | Notes |
| --- | --- | --- |
| `OMED_DB_URL` | api | Postgres connection |
| `OMED_DB_DEV_URL` | api | Clean dev Postgres database used by Atlas for diff/validation (`omed_dev`) |
| `OMED_DB_MIGRATE_ON_START` | api | Apply pending versioned migrations from `apps/api/migrations` on API startup (defaults to `false`) |
| `OMED_DB_AUTO_MIGRATE` | api | Run Ent `Schema.Create` automatically on startup (defaults to `false`) |
| `OMED_TRUSTED_ORIGINS` | api | Comma-separated CORS origins |
| `OMED_AUTH_SECRET` | api | Secret for session tokens and state signing |
| `OMED_SESSION_COOKIE_NAME` | api | Session cookie name (defaults to `omed_session`) |
| `OMED_GOOGLE_ID` / `OMED_GOOGLE_SECRET` | api | Optional, Google login |
| `OMED_GITHUB_ID` / `OMED_GITHUB_SECRET` | api | Optional, GitHub login |
| `OMED_REDIS_URL` | api | Planned (not yet used by application code) |
| `OMED_KAFKA_BROKERS` | api | Planned (not yet used by application code) |
| `OMED_API_URL` | api | Defaults to `http://localhost:8001` |
| `OMED_S3_*` | api | S3/RustFS storage for attachments (`OMED_S3_ENDPOINT`, `OMED_S3_ACCESS_KEY`, `OMED_S3_SECRET_KEY`, `OMED_S3_REGION`, `OMED_S3_FORCE_PATH_STYLE`) |
| `OMED_CMS_MEDIA_*` | api | CMS media upload limits (`OMED_CMS_MEDIA_MAX_SIZE_MB`, `OMED_CMS_MEDIA_ALLOWED_TYPES`) |
| `VITE_PUBLIC_URL` | web | Public dashboard URL |
| `VITE_API_URL` | web | Defaults to `http://localhost:8001` |
| `VITE_CMS_MEDIA_*` | web | CMS media upload limits (`VITE_CMS_MEDIA_MAX_SIZE_MB`, `VITE_CMS_MEDIA_ALLOWED_TYPES`) |

## Database Migrations (Ent + Atlas)

PostgreSQL tables are organized into module-scoped schemas matching the backend modules: **`core`**, **`fin`**, and **`cms`**. Each entity under `apps/api/ent/schema/` declares its target schema via `entsql.Schema("<module>")`.

Versioned SQL migrations live in `apps/api/migrations/` alongside `atlas.sum` and are configured via `apps/api/atlas.hcl`:

```bash
cd apps/api && go generate ./ent       # regenerate Ent after editing apps/api/ent/schema/*
cd apps/api && go run ./cmd/migrate <name> # generate a new versioned migration in apps/api/migrations
bun run db:migrate                     # apply pending migrations via Atlas CLI
cd apps/api && atlas migrate status --env local   # inspect migration status
cd apps/api && atlas migrate validate --env local # validate checksums & replay on omed_dev
```

## OpenAPI & Types

The OpenAPI v3.1 spec is generated from the Swaggo annotations in `apps/api`, then converted to TypeScript types in `packages/openapi`:

```bash
bunx turbo run oa:gen   # swag init in apps/api
bunx openapi-typescript apps/api/docs/swagger.json -o packages/openapi/src/api.ts
```

Commit the results (`apps/api/docs/*` and `packages/openapi/src/api.ts`) whenever annotations or response models change.

## Common Commands

```bash
bun run dev          # all apps, watch mode
bun run build        # build packages/apps that define a build script
bun run typecheck    # TypeScript typecheck
bun run lint         # Biome check (lint + format)
bun run format       # Biome auto-fix (check --write)
bun run test         # tests via turbo (see note below)
bun run e2e          # end-to-end tests
bun run db:diff      # generate versioned migration from Ent schemas
bun run db:migrate   # apply pending Atlas database migrations

```

### Testing

- **API (Go):** `cd apps/api && go test ./...`. API tests are not part of `bun run test` because `apps/api` has no `test` script; CI runs them directly.
- **E2E:** `bun run e2e`. The runner starts `api` and `web` automatically if they are not already running (disable with `E2E_AUTO_START=false`). Add `HEADED=true` to watch the browser. Run `bunx playwright install chromium` once beforehand.

## Docker

All images are built from the repo root (context `.`):

```bash
docker build -f apps/api/Dockerfile -t omed-api .
docker build -f apps/web/Dockerfile -t omed-web .
```

The `build.yml` workflow pushes images to `ghcr.io/<owner>/omed-<app>` (for example `ghcr.io/kilip/omed-api`), with `nightly`/`sha-*` tags for pushes to `main` and semver + `latest` for releases.

### Web runtime config

`VITE_*` values are baked in at build time. The `omed-web` image can override them at container start through `OMED_WEB_*` env vars (`OMED_WEB_API_URL`, `OMED_WEB_PUBLIC_URL`, `OMED_WEB_ATTACHMENT_MAX_SIZE_MB`, `OMED_WEB_ATTACHMENT_ALLOWED_TYPES`, `OMED_WEB_CMS_MEDIA_MAX_SIZE_MB`, `OMED_WEB_CMS_MEDIA_ALLOWED_TYPES`). `apps/web/docker-entrypoint.sh` renders them into `/config.js`, which the app reads before falling back to the build-time values:

```bash
docker run -p 3000:3000 -e OMED_WEB_API_URL=https://api.example.com omed-web
```

### Running Migrations in Production

The `omed-api` image embeds `apps/api/migrations` in `/api` and also includes `/atlas`, `/migrations`, and `/atlas.hcl`, supporting two deployment patterns:

1. **Dedicated Migration Init-Container / Job (recommended for multi-replica deployments):**
   Run the same `omed-api` image with `["/api", "migrate"]` (or `["/atlas", "migrate", "apply", "--config", "file:///atlas.hcl", "--env", "local"]`) before starting the API service.
2. **Single-Container Auto-Migrate on Startup:**
   Set `OMED_DB_MIGRATE_ON_START=true` on the `omed-api` container to automatically apply pending versioned migrations (with a PostgreSQL advisory lock) before listening on port `8001`.

## Kubernetes (Helm)

The Helm chart in [`deploy/helm/omed`](./deploy/helm/omed) deploys `api` and `web`, runs migrations as a pre-install/pre-upgrade hook Job, and exposes both through an Ingress. PostgreSQL, S3, and SMTP are external.

```bash
helm install omed oci://ghcr.io/kilip/charts/omed \
  --set secrets.existingSecret=omed-secrets \
  --set ingress.web.host=app.example.com \
  --set ingress.api.host=api.example.com
```

See the [chart README](./deploy/helm/omed/README.md) for secrets, values, and URL derivation.

## Contributing

1. Branch off `main`.
2. Commit using [Conventional Commits](https://www.conventionalcommits.org). Scope is required: `auth`, `web`, `api`, `e2e`, `deps`, `ci`, `release`, `tools`, `deploy`, `docs` (validated by commitlint). Prefix the subject with an emoji, e.g. `feat(api): ✨ add auth` (see [AGENTS.md](./AGENTS.md)).
3. The pre-commit hook runs `biome check --staged`; make sure `bun run lint` and the relevant tests pass.
4. Open a pull request against `main`. CI runs the API tests and E2E.

Releases and `CHANGELOG.md` are managed automatically by release-please from commits on `main`.

Guidance for AI coding agents is in [AGENTS.md](./AGENTS.md); dashboard visual guidelines are in [BRANDING.md](./BRANDING.md).
