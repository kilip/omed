# Omed

[![codecov](https://img.shields.io/codecov/c/github/kilip/omed)](https://codecov.io/gh/kilip/omed)

A demo project on steroids

The monorepo is managed with [Bun workspaces](https://bun.sh/docs/install/workspaces) and [Turborepo](https://turbo.build/repo).

## Repository Structure

```
omed/
├── apps/
│   ├── auth/          # @omed/auth        - Authentication service (ElysiaJS + Better Auth)
│   ├── api/           # @omed/api         - REST backend (Go, Fiber v3, Ent, Casbin, Swaggo)
│   └── web/           # @omed/web         - Web dashboard (React Router v8 SPA, Ant Design)
├── packages/
│   ├── better-auth/   # @omed/better-auth - Better Auth + Drizzle configuration (server & client)
│   ├── openapi/       # @omed/openapi     - TypeScript types generated from the `apps/api` OpenAPI spec
│   └── tsconfig/      # @omed/tsconfig    - Shared base tsconfig
├── e2e/               # e2e               - End-to-end tests (Cucumber + Playwright)
├── .devcontainer/     # Full dev environment (tools + Postgres, Redis, RustFS, Kafka)
├── .github/           # CI, image builds, release-please, Renovate
├── AGENTS.md          # Conventions for AI coding agents (CLAUDE.md and GEMINI.md point here)
├── BRANDING.md        # Dashboard visual guidelines / design tokens
└── turbo.json
```

| Package | Description | Port |
| --- | --- | --- |
| `apps/auth` | Login, sessions, and JWT issuer (Better Auth `admin` + `jwt` plugins). Google/GitHub social login. | 8001 |
| `apps/api` | REST backend. Verifies JWTs via the JWKS from `apps/auth`, Ent ORM, Casbin authorization, OpenAPI v3.1 spec via Swaggo. | 8002 |
| `apps/web` | SPA dashboard (`ssr: false`) with a module launcher and i18n (id/en). | 3001 |
| `packages/better-auth` | Better Auth instance, Drizzle schema (Postgres schema `auth`), zod-validated env. | - |
| `packages/openapi` | `src/api.ts` generated by `openapi-typescript`, consumed by `openapi-fetch` in the dashboard. | - |
| `e2e` | End-to-end tests (Cucumber + Playwright). | - |

## Architecture

```
 Browser ──► apps/web ──(login)──► apps/auth ──► Postgres (schema `auth`)
     │                                  │
     │  Bearer JWT                      │ JWKS
     └────────────► apps/api ◄──────────┘
                       │
                       └──► Postgres (Ent)
```

- `apps/auth` issues JWTs. `apps/api` verifies them with the JWKS, matches `iss`/`aud` against `AUTH_URL`.
- `apps/auth` only handles identity (credentials, sessions, JWT). `apps/api` is the source of truth for users, workspaces, and memberships.
- Authorization in `apps/api` is **workspace based**: every user gets a personal workspace, can create more, and can invite other users. Roles are assigned per workspace membership, plus a global `superadmin` (used for system-wide operations like `/users`). Global `superadmin` does not automatically bypass workspace access checks—a `superadmin` cannot access or read workspace resources unless explicitly added as a member or owner of that workspace.
- Modules in `apps/api` register their roles & permissions in code via `authz.AddRole` in `init()` (e.g. `fin:accountant` -> `fin:invoice read`). Permissions are verified per-request using an in-memory Casbin enforcer based on resolved workspace membership.
- The dashboard is split into modules (`sys`, `user`, `fin`, `web`), each under `apps/web/app/modules/<module>/`. A module declares its routes in `route.ts` and its launcher metadata (label, icon, etc.) in `module.ts`; there is no central registry file.

## Tech Stack

- **Backend:** Go, Fiber v3, Ent, Casbin, Swaggo
- **Auth:** ElysiaJS, Better Auth, Drizzle ORM
- **Frontend:** React 19, React Router v8 (SPA), Ant Design 6, Tailwind CSS 4, i18next
- **Data / infra (devcontainer & CI):** PostgreSQL 18, Redis 8, RustFS (S3-compatible), Apache Kafka (KRaft)
- **Tooling:** Bun, Turborepo, Biome, Husky + Commitlint, Air, Swag, Vitest, Cucumber, Playwright

> Redis, S3 (RustFS), and Kafka are currently only provisioned in the devcontainer and CI; no application code uses them yet.

## Prerequisites

- [Bun](https://bun.sh) `1.4.2` and Node.js `>= 22`
- [Go](https://go.dev) `1.27` (see `apps/api/go.mod`)
- Docker & Docker Compose (Postgres and supporting services)
- Go tools: [`air`](https://github.com/air-verse/air) and [`swag`](https://github.com/swaggo/swag) v2

> Easiest path: open the repo in the **devcontainer** (or GitHub Codespaces). All tools, services, and environment variables are prepared, and `bun install` runs automatically.

## Getting Started

```bash
git clone https://github.com/kilip/omed.git
cd omed

bun install            # also installs git hooks (husky)

bun run dev            # run all apps (turbo)
```

Run a single app:

```bash
bunx turbo run dev --filter=@omed/auth
bunx turbo run dev --filter=@omed/api
bunx turbo run dev --filter=@omed/web
```

Once running: dashboard at <http://localhost:3001>, auth at <http://localhost:8001> (OpenAPI docs at `/openapi`), API at <http://localhost:8002>.

### Environment

In the devcontainer all values below are set through `.devcontainer/compose.yaml`. Outside the devcontainer, each app reads its own git-ignored `.env`: copy `apps/api/.env.example`, `apps/auth/.env.example`, and `apps/web/.env.example` to `.env` in the same directory (`cp apps/<app>/.env.example apps/<app>/.env`).

| Variable | Used by | Notes |
| --- | --- | --- |
| `OMED_DB_URL` | auth, better-auth, api | Postgres connection (Better Auth uses schema `auth`) |
| `OMED_TRUSTED_ORIGINS` | auth, api | Comma-separated CORS origins |
| `OMED_AUTH_URL` | auth, api, e2e | Public auth URL (also the JWT `iss`/`aud`) |
| `OMED_AUTH_SECRET` | auth | Better Auth secret (change in production) |
| `OMED_GOOGLE_ID` / `OMED_GOOGLE_SECRET` | auth | Optional, Google login |
| `OMED_GITHUB_ID` / `OMED_GITHUB_SECRET` | auth | Optional, GitHub login |
| `OMED_JWKS_URL` | api | JWKS endpoint of the auth service. |
| `OMED_REDIS_URL` | api, auth | Redis |
| `OMED_KAFKA_BROKERS` | api, auth | Kafka Brokers |
| `OMED_API_URL` | api | Defaults to `http://localhost:8002` |
| `OMED_S3_*` | api | S3/RustFS storage for attachments (`OMED_S3_ENDPOINT`, `OMED_S3_ACCESS_KEY`, `OMED_S3_SECRET_KEY`, `OMED_S3_REGION`, `OMED_S3_FORCE_PATH_STYLE`) |
| `VITE_AUTH_URL`, `VITE_PUBLIC_URL` | web | Auth URL and public dashboard URL |
| `VITE_API_URL` | web | Defaults to `http://localhost:8002` |

## OpenAPI & Types

The OpenAPI v3.1 spec is generated from the Swaggo annotations in `apps/api`, then converted to TypeScript types in `packages/openapi`:

```bash
bunx turbo run oa:gen   # swag init in apps/api
bunx openapi-typescript apps/api/docs/swagger.json -o packages/openapi/src/api.ts
```

Commit the results (`apps/api/docs/*` and `packages/openapi/src/api.ts`) whenever annotations or response models change.

## Common Commands

```bash
bun run dev          # all apps, watch mode
bun run build        # build packages/apps that define a build script
bun run typecheck    # TypeScript typecheck
bun run lint         # Biome check (lint + format)
bun run format       # Biome auto-fix (check --write)
bun run test         # tests via turbo (see note below)
bun run e2e          # end-to-end tests
```

### Testing

- **API (Go):** `cd apps/api && go test ./...`. API tests are not part of `bun run test` because `apps/api` has no `test` script; CI runs them directly.
- **Better Auth:** `bun --filter @omed/better-auth test` (Vitest).
- **E2E:** `bun run e2e`. The runner starts `auth`, `web`, and `api` automatically if they are not already running (disable with `E2E_AUTO_START=false`). Add `HEADED=true` to watch the browser. Run `bunx playwright install chromium` once beforehand.

## Docker

All images are built from the repo root (context `.`):

```bash
docker build -f apps/api/Dockerfile  -t omed-api .
docker build -f apps/auth/Dockerfile -t omed-auth .
docker build -f apps/web/Dockerfile -t omed-web .
```

The `build.yml` workflow pushes images to `ghcr.io/<owner>/omed/<app>` (`nightly`/`sha-*` tags for pushes to `main`, semver + `latest` for releases).

## Contributing

1. Branch off `main`.
2. Commit using [Conventional Commits](https://www.conventionalcommits.org). Allowed scopes: `auth`, `web`, `api`, `e2e`, `deps`, `ci`, `release`, `tools`, `docs` (validated by commitlint). End every subject with an emoji shortcode, e.g. `feat(api): add auth :rocket:` (see [AGENTS.md](./AGENTS.md)).
3. The pre-commit hook runs `biome check --staged`; make sure `bun run lint` and the relevant tests pass.
4. Open a pull request against `main`. CI runs the API tests, Better Auth tests, and E2E.

Releases and `CHANGELOG.md` are managed automatically by release-please from commits on `main`.

Guidance for AI coding agents is in [AGENTS.md](./AGENTS.md); dashboard visual guidelines are in [BRANDING.md](./BRANDING.md).
