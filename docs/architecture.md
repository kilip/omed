# Architecture

Omed is a modular, workspace-oriented monorepo managed with [Bun workspaces](https://bun.sh/docs/install/workspaces) and [Turborepo](https://turbo.build/repo).

```
 Browser ──► apps/web ──► apps/api ──► Postgres (Ent)
```

## Repository Structure

```
omed/
├── apps/
│   ├── api/           # @omed/api         - REST backend (Go, Fiber v3, Ent, Casbin, Swaggo)
│   └── web/           # @omed/web         - Web dashboard (React Router v8 SPA, Ant Design)
├── packages/
│   ├── openapi/       # @omed/openapi     - TypeScript types generated from the `apps/api` OpenAPI spec
│   └── tsconfig/      # @omed/tsconfig    - Shared base tsconfig
├── e2e/               # e2e               - End-to-end tests (Cucumber + Playwright)
├── docs/              # Technical documentation and design specs
├── deploy/helm/omed/  # Kubernetes Helm chart
├── .devcontainer/     # Full dev environment (tools + Postgres, Redis, RustFS, Kafka)
├── .github/           # CI, image builds, release-please, Renovate
├── AGENTS.md          # Conventions for AI coding agents (CLAUDE.md and GEMINI.md point here)
├── BRANDING.md        # Dashboard visual guidelines / design tokens
└── turbo.json
```

| Package | Description | Default Port |
| --- | --- | --- |
| `apps/api` | REST backend and MCP server. Authentication, sessions, Ent ORM, Casbin authorization, OpenAPI v3.1 spec via Swaggo. | `8001` |
| `apps/web` | SPA dashboard (`ssr: false`) with a module launcher and i18n (`id`/`en`). | `3000` |
| `packages/openapi` | `src/api.ts` generated by `openapi-typescript`, consumed by `openapi-fetch` in the dashboard. | - |
| `e2e` | End-to-end tests (Cucumber + Playwright). | - |

## Core Principles

- **Identity & Workspaces:** `apps/api` handles authentication, sessions, and is the source of truth for users, workspaces, and memberships. Every user gets a personal workspace, can create additional workspaces, and can invite collaborators.
- **Workspace-Scoped Authorization:** Authorization in `apps/api` is enforced per workspace. Modules register their roles and permissions in code via `authz.AddRole` in `init()` (for example, `fin:accountant` -> `fin:invoice read`). Permissions are verified per request using an in-memory Casbin enforcer against the user's resolved workspace membership.
- **Multi-Schema Database Isolation:** PostgreSQL tables are isolated into module-scoped schemas matching the backend modules: `core`, `fin`, `cms`, and `agent`.
- **Self-Contained Frontend Modules:** The dashboard is split into matching modules (`core`, `fin`, `cms`, `agent`) under `apps/web/app/modules/<module>/`. Each module declares its routes in `route.ts` and its launcher metadata in `module.ts` without a central registry file.

## Modules & Routes

### Core (`core`)

- `/core`: Workspace dashboard and overview.
- `/core/workspaces/new`, `/core/workspaces/:id`: Create and edit workspaces.
- `/core/members`, `/core/members/new`, `/core/members/:id`: Manage workspace members and role assignments.
- `/core/invitations`: View and respond to workspace invitations.
- `/core/access-tokens`: Personal Access Token (PAT) management for external MCP clients (create tokens with 30/90/365-day expiry, one-time plaintext reveal, list active/expired/revoked tokens, and revoke).

### Finance (`fin`)

- `/fin`, `/fin/overview`: Finance launcher and overview dashboard with financial status metrics.
- `/fin/onboarding`: 2-step financial onboarding wizard configuring currency, fiscal period, and Chart of Accounts (CoA) template.
- `/fin/settings`: Finance workspace settings for currency format, fiscal periods, and FX accounts.
- `/fin/accounts`: Tree-table Chart of Accounts with account type, balance classification, active state, and ledger navigation.
- `/fin/periods`: Fiscal period management.
- `/fin/opening-balance`: Opening balance configuration across accounts.
- `/fin/income`, `/fin/income/new`, `/fin/income/:id`, `/fin/income/:id/edit`: Multi-item income documents with status filtering (`Draft`, `Posted`), search, file attachments, and immediate posting or draft workflows.
- `/fin/expense`, `/fin/expense/new`, `/fin/expense/:id`, `/fin/expense/:id/edit`: Multi-item expense documents with status filtering (`Draft`, `Posted`), search, file attachments, and immediate posting or draft workflows.
- `/fin/transactions`, `/fin/transactions/new`, `/fin/transactions/:id`, `/fin/transactions/:id/edit`: Business transactions with search, reference/source/date filtering, and associated journal entries.
- `/fin/journal`, `/fin/journal/new`, `/fin/journal/:id`: Double-entry journal vouchers (`PostingsEditor`) with status workflows (post, reverse with date override, void) and ledger postings.
- `/fin/ledger`: General Ledger view (`GET /workspaces/{wid}/fin/accounts/{id}/ledger`) with account selector, running balances, and deep-links to journal entries.
- `/fin/trial-balance`: Financial trial balance reports and summaries.

### CMS (`cms`)

- `/cms`: CMS overview.
- `/cms/posts`, `/cms/posts/new`, `/cms/posts/:id`: Blog posts with search, status filters (`Draft`, `Scheduled`, `Published`), auto-slug, excerpt, Markdown editor (write/preview), cover media picker, and publishing controls.
- `/cms/pages`, `/cms/pages/new`, `/cms/pages/:id`: Standalone pages with auto-slug, Markdown editor, and publishing controls.
- `/cms/media`: Media library with drag-and-drop uploads, metadata editing (title, alt text, caption, public toggle), public URL copying, and in-use delete protection.
- **API Endpoints:**
  - Admin API: authenticated workspace-scoped CRUD and publishing endpoints under `/workspaces/:wid/cms/{posts,pages,media}`.
  - Public API: unauthenticated read-only endpoints under `/public/workspaces/:wid/cms/{posts,pages,media}`.

### Agent (`agent`)

- `/agent`, `/agent/providers`, `/agent/providers/new`, `/agent/providers/:id/edit`: LLM provider directory and configuration supporting Anthropic, OpenAI, DeepSeek, Ollama, and custom OpenAI-compatible endpoints with AES-256-GCM credential encryption, default provider and model selection, and live connection testing.
- **Roles:** `agent:admin` (full management access) and `agent:viewer` (view providers and configurations).
- **API Endpoints:** authenticated workspace-scoped CRUD, model listing, and connection testing endpoints under `/workspaces/:wid/agent/providers*`.

## Model Context Protocol (MCP) Server

`apps/api` exposes a built-in Model Context Protocol server at `/mcp` so external AI assistants and MCP clients can securely interact with workspace data.

- **Transport:** Unified Streamable HTTP transport (`github.com/modelcontextprotocol/go-sdk`) operating in stateless mode (`Stateless: true`, `JSONResponse: true`).
- **Authentication:** Bearer Personal Access Token (`Authorization: Bearer omed_pat_...`). Session cookies are bypassed at `/mcp`, and PATs cannot access regular REST endpoints.
- **Authorization:** Modules register tools during boot via `config.HasMCP` (`RegisterMCP(r *mcpx.Registrar) error`). Tools execute under the authenticated user identity with workspace permissions verified via Casbin.
- **Available Tools:**
  - `fin_period_overview`: Monthly financial revenue, expense, and net overview with previous-period comparison (requires `fin:account` `read`).
    - Arguments: `workspace_id` (required, `int64`), `from_month` (optional, `YYYY-MM`, default current month), `to_month` (optional, `YYYY-MM`, default current month, max 24 months), `compare_previous` (optional, `boolean`, default `true`).
  - `fin_account_balance`: Trial balance and account balances as of a date (requires `fin:account` `read`).
    - Arguments: `workspace_id` (required, `int64`), `as_of_date` (optional, `YYYY-MM-DD`, default today), `account` (optional, code prefix or case-insensitive name fragment). Returns at most 50 accounts (`truncated: true` if exceeded).
  - `fin_find_cashflow`: Search income and expense cashflow documents (requires `fin:transaction` `read` and `fin:account` `read`).
    - Arguments: `workspace_id` (required, `int64`), `type` (required, `income` or `expense`), `date_from` (optional, `YYYY-MM-DD`), `date_to` (optional, `YYYY-MM-DD`), `status` (optional, `draft` or `posted`), `query` (optional, description text search), `payment_account` (optional, code or name), `category_account` (optional, code or name), `limit` (optional, integer `1`–`50`, default `20`), `cursor` (optional, pagination cursor).

## Tech Stack

- **Backend & Auth:** Go, Fiber v3, Ent, Casbin, Swaggo, MCP Go SDK
- **Frontend:** React 19, React Router v8 (SPA), Ant Design 6, Tailwind CSS 4, i18next
- **Data & Infrastructure:** PostgreSQL 18, RustFS / S3-compatible object storage, SMTP mailer (plus Redis 8 and Apache Kafka provisioned in devcontainer/CI for future use)
- **Tooling:** Bun, Turborepo, Biome, Husky + Commitlint, Air, Swag, Atlas, Vitest, Cucumber, Playwright
